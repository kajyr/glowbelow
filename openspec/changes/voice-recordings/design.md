## Context

- `src/audio/facts.ts` finds recordings at build time with `import.meta.glob('../../voice/*/*.mp3')`. A recording wins over the device voice.
- Facts are `facts.<stamp>` keys in `src/i18n/en.json`; `it.json` arrives with `iteration-7-italian`.
- `tools/` holds plain-Python generators (models, icons); generated files are committed.

## Goals / Non-Goals

**Goals:**
- A grown-up with only a phone can record, name and hand over the files
- Mistakes (wrong name, huge file, stale script) are caught by `npm test`, not on the tablet

**Non-Goals:**
- No recording inside the game (no microphone, no upload)
- No audio processing in the repo (no ffmpeg dependency); the tips give one optional command
- No subtitles or transcripts on screen (the game stays text-free)

## Decisions

### Script generated by `tools/make_voice_script.py` into `docs/voice/README.md`
- Reads every `src/i18n/*.json`, writes one table per language: stamp, text, file name, plus the tips
- Plain Python, like the other generators. Alternative: a TS script run through `vite-node` (one more way of running tools)
- Staleness test in Vitest: every `facts.*` text in each language file must appear in the README exactly, next to its file name

### Checks in a Vitest test next to `facts.ts`
- Lists `voice/**` with Node `fs` (not the glob), so a misnamed or wrong-type file is caught too
- Validates `<lang>/<stamp>.mp3` against the language files and their `facts.*` keys
- Size limits: 250 KB per file, 3 MB in all
  - A 10 s fact at 64 kbps mono is about 80 KB, so this leaves headroom
  - 3 MB keeps the whole precache under about 5 MB
- Alternative: checking in the Vite build (would only fail at build, not in `npm test`)

### Format: `.mp3` only
- Plays on iOS Safari, Chrome and Firefox; one extension keeps the rules simple
- Phone voice memos are usually `.m4a`: the tips include an optional `ffmpeg` line to convert them (mono, 64 kbps, silence trimmed), and tell the reader to hand the file over if they can't convert it themselves

## Risks / Trade-offs

- [Recordings and facts drift when a fact is reworded] → The script test fails on changed text. The recording itself can't be checked against the words, so the tips say to re-record a fact when its line in the script changes.
- [Loudness differs between recordings and the game's sounds] → The tips ask for a steady distance from the phone. The `ffmpeg` line also normalises loudness.
- [Private voice in a public repository] → Recordings are committed and published with the game. The script says this plainly, so the grown-up can decide.

## Migration Plan

Nothing to migrate: with no recordings, behaviour is unchanged.
